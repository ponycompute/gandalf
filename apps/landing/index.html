The problem

Every agent wants its own folder.

You write a great skill for Claude Code. Then you copy it into Cursor. Then Codex. Then you fix a bug in one copy and forget the other three. A month later nobody knows which version is real.

~/.claude/skills/pdf ~/.cursor/skills/pdf edited ~/.codex/skills/pdf ~/.gemini/skills/pdf stale ~/.goose/skills/pdf broken link

How it works

Three verbs. Zero surprises.

  1. 01

    Adopt

    Gandalf scans every agent's folder and offers to move the skills you already have into one library at ~/.gandalf/skills, then links them back. 

    $ gandalf skills adopt --all
  2. 02

    Install

    Add a skill from a local folder or any git URL, pinned to a commit. Choose which agents get it — or give it to all of them. 

    $ gandalf skills install github.com/acme/skills --subpath pdf
  3. 03

    Sync

    Every agent folder is made to match the library. Linked where the agent follows links, copied where it doesn't. Run it again and nothing happens. 

    $ gandalf skills sync

Plan, then apply

See every change before a single byte moves.

Every write starts as a plan. --dry-run prints it; the app shows it as a preview sheet. Apply re-derives the same plan, so what you saw is exactly what runs — or nothing does.

  • Same plan in the CLI and the desktop app
  • A lock so two runs never collide
  • Copies go to the Trash, never rm -rf

Built to be trusted with your home folder

Gandalf never replaces what you placed.

✗

Conflicts are reported, not resolved for you

A folder you made, a link you set up, a copy you edited — gandalf sees it, names it, and leaves it alone. You decide; it explains what to do next.

✗ frontend-design in Cursor — A skill you placed there uses this name. gandalf never replaces it. Rename or move it, then Sync.
◐

Edits are sacred

Changed a library skill by hand? Updates stop for that skill until you say so.
