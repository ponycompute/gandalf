Careful with your home folder

Your skills live in dotfolders next to everything else you care about. gandalf treats them that way.

link cursor/pdf copy codex/pdf record enable pdf

Plans before it writes

Every change is shown first. What you approve is exactly what runs, or nothing does.

✗ A skill you placed uses this name

Never replaces your files

A folder you made or a copy you edited is reported and left alone. You decide.

~/.gandalf .claude .cursor

Local and plain

One folder of skills on your disk, linked or copied into each agent. No account, no cloud.

Same thing in your terminal

The app and the CLI share one engine, so a --dry-run prints the same plan the app shows you. 

$ gandalf skills sync --dry-run
  link   ~/.cursor/skills/pdf -> ~/.gandalf/skills/pdf
  copy   ~/.codex/skills/pdf <- ~/.gandalf/skills/pdf
not doing
  conflict  ~/.gemini/skills/frontend-design  a skill you placed
            already uses this name; gandalf never replaces it

Open source by default

gandalf moves files in your home folder. You should be able to read every line that does it.

ponycompute/gandalf on GitHub

To the people who write skills,

A good skill is a small piece of how you work. It shouldn't matter which agent you open today — it should already know.

Instead, every agent wants its own folder. You copy, you edit one copy, you forget the others, and a month later nobody knows which version is real.

We think your skills belong in one place you own, in plain files, with a tool that explains every change before making it and never overwrites your work.

gandalf is our attempt at that tool.

— the gandalf team
