Gandalf is a local tool for people who use more than one coding agent. Each agent keeps its skills in its own directory and its own record of what it did, so switching agents mid-task costs you twice. Gandalf lines the skills up across Claude Code, Codex, and Cursor, and hands work from Claude Code to Codex and back.

## What Gandalf does

- **Lists skills across agents.** Run `gandalf` to see every skill and whether each agent has it.
- **Detects differing copies.** Skills are compared by content hash, so an edited copy shows up as `diverged` instead of passing as installed.
- **Syncs skills.** `gandalf skill sync` copies skills to the agents missing them. Copies that differ are only overwritten when you name the agent whose copy wins.
- **Adds and removes skills.** Install a local skill directory into every agent at once, or remove it everywhere.
- **Keeps what it displaces.** Replaced and removed skills move to `~/.gandalf/trash` instead of being deleted.
- **Hands work over.** After `gandalf init`, a local service records what Claude Code and Codex did in a project and serves the next agent a handoff contract over MCP. See [`gandalf` work handoff](/cli/handoff).

## What Gandalf does not do

- It does not manage MCP servers, hooks, permissions, or agent settings, beyond registering its own handoff integration.
- It does not download skills from the network; `gandalf skill add` takes a local directory.
- It does not execute commands, launch agents, or assign work.
- It does not need an account and has no cloud sync.

## Current support

Skills: Claude Code, Codex, and Cursor. Work handoff: Claude Code and Codex. Gandalf runs on macOS. See the [support matrix](/reference/support-matrix).
