The trust contract is the safety boundary Gandalf enforces. Every claim below is a runtime rule, not a suggestion.

## Reading

- `gandalf`, `gandalf skill list`, and `gandalf skill show` only read files.
- Gandalf never executes a skill, a script inside a skill, or any agent tool.
- Gandalf never uses the network. There is no account, telemetry, or update check.

## Writing

- `gandalf skill add`, `sync`, and `remove` write only inside the agent skill directories (`~/.claude/skills`, `~/.codex/skills`, `~/.cursor/skills`, or their project counterparts with `--scope project`) and `~/.gandalf/trash`.
- Every mutating command accepts `--dry-run`, which prints the same changes without writing.
- Skill names are restricted to a single safe directory name, so a name can never point outside a skill directory.
- New copies are staged in a hidden sibling directory and renamed into place, so an agent never reads a half-written skill.

## Nothing is deleted outright

- A replaced or removed skill is moved to `~/.gandalf/trash/<timestamp>/<scope>/<agent>/<name>`. Move it back to undo.
- Gandalf never empties the trash. Delete it yourself when you no longer need it.

## Differing copies are never overwritten silently

- `gandalf skill sync` leaves `diverged` skills untouched and exits with status 1 until you pass `--from <agent>`.
- `gandalf skill add` leaves an agent's differing copy untouched and exits with status 1 unless you pass `--force`.

## Symlinks

- A skill directory that is a symlink is reported as `(link)`. Gandalf never writes through it or replaces it; `gandalf skill remove` only removes the link, never its target.
- Inside a skill, relative symlinks that stay within the skill are copied as links. Absolute links and links that leave the skill directory are not copied.
