# v0.9.0 Release Notes

Release title: `v0.9.0 - First-Run Overview and Secret Leak Fixes`

## Summary

v0.9.0 makes the first run of Gandalf useful on its own. Running `gandalf` with no arguments now prints an overview of your agent setup: every MCP server lined up across Claude Code, Codex, and Cursor, mismatches between agents, and the few issues worth fixing first. No manifest or configuration is needed.

This release also closes several paths where credentials from agent configs reached Gandalf's output and snapshots. **If you shared `--json` output from v0.8.2 or earlier, read the security section.**

## Breaking changes

- **`gandalf` with no arguments no longer opens the TUI.** It prints the overview. Use `gandalf tui` to open the interactive console.
- **MCP server restore refuses redacted values.** If a snapshot holds a masked copy of an MCP entry (env reduced to key names, or `[redacted]` credentials), restoring that single entry now fails with an explanation instead of writing the masked value into your config. Restore the whole config file from a content-backed snapshot instead.

## Highlights

- **First-run overview (`gandalf`, `gandalf overview`)**: a cross-agent MCP server table with mismatch notes (for example, `versions differ: latest vs 0.0.20`), the top findings, and next steps, including per-agent restore-point commands. A test runs every suggested command so none of them fail. `--json` is supported.
- **Plaintext secret detection (`PLAINTEXT_SECRET`)**: flags credentials stored in MCP configs (env values, headers, tokens in `args`, passwords inside connection URLs). Gandalf reports the location only, never the value.
- **Hook network egress (`HOOK_NETWORK_EGRESS`)**: flags hooks that run `curl`, `wget`, `nc`, and similar tools, with the destination host.
- **Claude Code user MCP servers**: servers added with `claude mcp add --scope user` (stored in `~/.claude.json`) are now discovered by scan, overview, and drift checks. The file stays metadata-only and these entries are redacted.
- **Scope-accurate wildcard warning**: `PERMISSION_WILDCARD_ADDED` now names the real scope instead of always saying "Project settings".

## Security fixes

### What was exposed in v0.8.2 and earlier

Two kinds of values escaped redaction:

- Codex TOML inline tables, such as `env = { GITHUB_TOKEN = "..." }`, were stored verbatim.
- Credentials inside strings, such as `postgresql://user:password@host` in MCP `args` or `https://user:password@host` in a remote MCP `url`, were not masked, because the containing key is not secret-like.

These values appeared in:

- `gandalf scan --json` and `gandalf report --json` output.
- Snapshots of Codex and Cursor setups (`evidence.json` and `graph.json` under `~/.gandalf/<agent>/<snapshot>/`), and therefore in `snapshot show`, `diff`, `restore`, and `report` JSON output for those snapshots.

### What v0.9.0 changes

- New scans and snapshots mask these values. The shared redactor masks only the secret part of a string (`postgresql://user:[redacted]@host`), so values stay recognizable.
- All JSON output is masked on the way out, so older snapshots no longer print raw values either.
- A regression test plants secrets in every supported config format and asserts they never reach `scan`, `report`, or `overview` output.

### What you should do

- **Rotate** any credential in `~/.codex/config.toml`, `~/.cursor/mcp.json`, or `~/.claude.json` if you shared `--json` output from Gandalf, for example in an issue, CI log, or chat.
- **Old snapshots stay on disk unchanged.** v0.9.0 masks them in output, but the files under `~/.gandalf/codex/` and `~/.gandalf/cursor/` still contain the raw values. Delete those snapshot folders if you want the values gone, then take fresh restore points with `gandalf snapshot create --name <name> --agent <agent> --scope user`.
- **Bundles are unchanged by design.** A content bundle carries your config files byte for byte so it can restore them on another machine, which includes any credentials in them. Share content bundles only with people who should have those credentials, and use `bundle export --metadata-only` to share a setup for debugging. The bundle docs now say this explicitly.
