# v0.10.0 Release Notes

Release title: `v0.10.0 - Skills and Work Handoff, Rebuilt in Rust`

## Summary

v0.10.0 is a different product from v0.9.0. Gandalf is now a tool for people who use more than one coding agent, and it does two things:

- **Skills**: it shows the skills installed in Claude Code, Codex, and Cursor side by side, flags the ones that are missing or differ, and syncs them.
- **Work handoff**: it records what Claude Code and Codex did in a project and hands the next agent a contract with the status, completed steps, blockers, and next actions.

The team manifest (`gandalf.toml`), MCP and hook management, snapshots, restore, bundles, and the TUI console from earlier versions are gone. **If you rely on any of those, stay on v0.9.0.**

The CLI is rewritten in Rust and runs on macOS only.

## Breaking changes

- **Every v0.9.0 command is removed.** `init` (manifest), `export`, `import`, `check`, `apply`, `scan`, `overview`, `snapshot`, `diff`, `restore`, `bundle`, `timeline`, `doctor` (readiness), `report`, `tui` (setup console), and `boost` no longer exist. `init`, `doctor`, and `tui` are names of new, unrelated commands.
- **`gandalf.toml` is no longer read.** There is no drift gate and no `gandalf check --ci`.
- **The GitHub Action is removed.** Workflows that use this repository as an action will fail.
- **Linux is no longer supported.** Binaries are published for macOS on Apple silicon and Intel. `install.sh` exits with a message on Linux.
- **Homebrew is no longer updated.** The tap stays at v0.9.0. Install with the install script.
- **Data from earlier versions is not used.** Snapshots and stores under `~/.gandalf` from v0.9.0 and earlier are left in place and ignored.
- **`gandalf` with no arguments lists skills** instead of printing the MCP overview.

## Install

```bash
curl -fsSL https://raw.githubusercontent.com/ponycompute/gandalf/main/install.sh | sh
```

The script downloads this release for your Mac, verifies its checksum, and installs `gandalf` to `~/.local/bin`. Set `GANDALF_INSTALL_DIR` to install somewhere else. If you installed an earlier version with Homebrew, run `brew uninstall gandalf` first so the old binary does not shadow the new one.

## Skills

Works for Claude Code, Codex, and Cursor, with no setup and no background service.

- **`gandalf` / `gandalf skill list`**: one row per skill and one column per agent, with a status: `synced` (identical everywhere), `partial` (identical where present, missing in some agents), or `diverged` (copies differ). Copies are compared by content hash, so an edited copy is caught. `--scope user|project|all`, `--agent`.
- **`gandalf skill show <name>`**: where each copy lives, its short hash, and its `SKILL.md`.
- **`gandalf skill add <path>`**: installs a local skill directory into every agent.
- **`gandalf skill sync [name...]`**: copies skills to the agents missing them.
- **`gandalf skill remove <name>`**: removes a skill from every agent.

Safety rules:

- A copy that differs is never overwritten unless you pass `--from <agent>` to `sync` or `--force` to `add`. Otherwise the command leaves it alone and exits with status 1.
- Replaced and removed skills move to `~/.gandalf/trash`. Nothing is deleted.
- Every mutating command takes `--dry-run`.
- A skill directory that is a symlink is never written through; `remove` only removes the link.

## Work handoff

Works for Claude Code and Codex. Nothing is recorded until you opt in.

- **`gandalf init`** registers the integration with Claude Code and Codex, preserving your existing settings, and installs a background service for your user.
- **`gandalf work list|current|show <id>`**, **`gandalf handoff <id>`**, and **`gandalf search <query>`** read tracked work for the current project. **`gandalf tui`** browses it.
- **`gandalf mcp --provider claude|codex`** serves the same context to an agent over MCP. `init` sets this up.
- **`gandalf status`**, **`gandalf doctor`**, and **`gandalf daemon start|stop|logs`** check and control the service.
- **`gandalf forget work <id>|project`** deletes recorded work.

What it stores and what it does not do:

- State lives in `~/.gandalf`, readable only by your user. Recorded transcript material is encrypted with a key held in the macOS keychain, and is shown redacted unless you pass `--raw`.
- Gandalf has no account and no cloud sync, and does not send your data to a remote server.
- Gandalf does not execute commands, launch agents, or assign work.

Work handoff is new in Gandalf and has had far less real-world use than the skill commands. Expect rough edges.

## Other changes

- Global flags are `--output text|json` and `--project-root <dir>`.
- Exit codes: `1` for a failed or refused skill operation, `2` for invalid arguments, `69` when a handoff command cannot reach the service.
- Releases are built from a Rust workspace. Building from source needs the toolchain pinned in `rust-toolchain.toml`; run `make build`.

## Verification

- `cargo fmt --check`, `cargo clippy --workspace --all-targets --all-features -- -D warnings`, and `cargo test --workspace --all-features` pass on macOS.
- The skill workflow is covered end to end against the built binary: add, sync, refusal of a diverged copy, `--from` resolution, remove, and trash recovery.
